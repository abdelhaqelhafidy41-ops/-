# المرحلة الثامنة: إصلاح ظهور الويدجت وتكرارها وخطأ Couldn't add widget

## السياق
لديك تطبيق Android إسلامي باسم مؤقت **نور المسلم** يحتوي على عدد كبير من الويدجت. عند فتح قائمة Widgets في Launcher تظهر الويدجت كلها بنفس الصورة والشكل، وتظهر جميعها باسم التطبيق نفسه وبمقاس واحد مثل 2x1، لذلك لا يستطيع المستخدم التمييز بينها. كما أن بعض الويدجت مكررة، وبعضها يفشل عند إضافته إلى الشاشة الرئيسية وتظهر رسالة:

```text
Couldn't add widget
```

المطلوب إصلاح المشكلة من جذورها داخل مشروع Android الحالي، وليس الاكتفاء بتغيير الصور داخل التطبيق.

---

## الهدف الأساسي

أعد بناء نظام تعريف الويدجت بحيث:

1. يظهر لكل Widget اسم واضح ومميز.
2. يظهر لكل Widget تصميم Preview يطابق الشكل الحقيقي الذي سيظهر على الشاشة الرئيسية.
3. يظهر لكل Widget وصف أو تصنيف مناسب عند دعم Launcher لذلك.
4. يظهر المقاس المناسب لكل Widget، وليس 2x1 لجميع الويدجت.
5. لا توجد تعريفات أو Providers مكررة.
6. كل Widget معلن في AndroidManifest يعمل فعليًا عند إضافته.
7. لا تظهر رسالة `Couldn't add widget`.
8. الويدجت التي تحتاج إعدادًا تفتح شاشة Configuration Activity صحيحة.
9. الويدجت التي لا تحتاج إعدادًا تُضاف مباشرة دون فشل.
10. تُحذف أو تُعطل الويدجت غير المكتملة بدل عرضها في قائمة المستخدم.

لا تعتبر المهمة مكتملة بتغيير اسم التطبيق أو الأيقونة العامة فقط. يجب أن يكون لكل Widget تعريف Android مستقل ومعاينة وتصميم ووظيفة صحيحة.

---

## أولًا: جرد الويدجت الحالية

قبل تعديل الكود، افحص المشروع كاملًا وأنشئ جدولًا بكل تعريفات الويدجت الموجودة، يشمل:

- اسم class أو AppWidgetProvider.
- اسم ملف `appwidget-provider` XML.
- اسم `receiver` في AndroidManifest.
- اسم الويدجت الظاهر للمستخدم.
- المقاسات الحالية.
- Preview الحالية.
- هل تستخدم RemoteViews أم Jetpack Glance.
- هل لها Configuration Activity.
- هل تعمل عند الإضافة.
- هل هي مكررة أو Alias لويدجت أخرى.

ابحث عن التكرار في:

- `AndroidManifest.xml`.
- ملفات `res/xml/*_widget_info.xml`.
- ملفات `res/values/strings.xml`.
- `activity-alias`.
- Classes مكررة أو Providers تشير إلى نفس XML.
- معرفات أو أسماء عامة متكررة.
- تعريفات قديمة بقيت بعد إعادة تسمية الويدجت.

بعد الجرد، أنشئ سجلًا واضحًا يبين ما تم الاحتفاظ به وما تم حذفه وسبب ذلك.

## ثانيًا: تعريف مستقل لكل Widget

لا تستخدم Provider واحدًا عامًا لجميع الويدجت مع صورة التطبيق كمعاينة. أنشئ تعريفًا مستقلًا لكل نوع Widget فعلي.

لكل Widget يجب توفير:

1. Class أو Provider مستقل باسم واضح، مثل:

```text
NextPrayerWidgetProvider
PrayerTimesWidgetProvider
AyahOfTheDayWidgetProvider
DailyDhikrWidgetProvider
QuranProgressWidgetProvider
TasbeehCounterWidgetProvider
QiblaWidgetProvider
HijriDateWidgetProvider
LastReadingWidgetProvider
WeatherWidgetProvider
DailyWorshipPlanWidgetProvider
QuranPlayerWidgetProvider
RamadanPrayerTimesWidgetProvider
```

2. ملف metadata مستقل في `res/xml/`، مثل:

```text
next_prayer_widget_info.xml
prayer_times_widget_info.xml
ayah_of_the_day_widget_info.xml
```

3. اسم ظاهر مستقل داخل `res/values/strings.xml`، مثل:

```xml
<string name="widget_name_next_prayer">الصلاة القادمة</string>
<string name="widget_name_prayer_times">مواقيت الصلاة</string>
<string name="widget_name_ayah_of_day">آية اليوم</string>
<string name="widget_name_daily_dhikr">ذكر اليوم</string>
<string name="widget_name_quran_progress">تقدم ختم القرآن</string>
```

لا تستخدم `@string/app_name` لجميع الويدجت. اسم التطبيق يمكن أن يظهر كاسم الحزمة أو المجموعة عند الحاجة، لكن اسم كل Widget يجب أن يكون مميزًا وواضحًا.

4. تصميم Layout أو Glance Composable مطابق للتصميم الفعلي.
5. Preview مستقلة تمثل نفس التصميم الحقيقي.
6. موارد مستقلة للألوان والأيقونات والنصوص.

## ثالثًا: إصلاح AndroidManifest

راجع كل تعريف `receiver` وأصلحه وفق توثيق Android الحالي. يجب أن يكون لكل Widget Receiver واحد فقط، مثل:

```xml
<receiver
    android:name=".widget.nextprayer.NextPrayerWidgetProvider"
    android:exported="true"
    android:label="@string/widget_name_next_prayer">
    <intent-filter>
        <action android:name="android.appwidget.action.APPWIDGET_UPDATE" />
    </intent-filter>
    <meta-data
        android:name="android.appwidget.provider"
        android:resource="@xml/next_prayer_widget_info" />
</receiver>
```

طبّق القواعد التالية:

- لا يوجد أكثر من Receiver لنفس Widget.
- لا يوجد أكثر من Provider يشير إلى نفس ملف XML إلا لسبب موثق.
- لا تستخدم `activity-alias` لإنشاء نسخ مكررة.
- اجعل `android:label` يشير إلى اسم Widget الفريد.
- استخدم `android:exported="true"` للـ Receiver المطلوب من Launcher، وفق متطلبات Android.
- لا تضف Intent Filters غير لازمة.
- لا تستخدم اسم التطبيق العام كـ label لكل Receiver.
- تأكد من أن package وnamespace وclass paths صحيحة.
- احذف التعريفات القديمة من Manifest وملفات الموارد بعد التأكد من عدم استخدامها.

بعد التعديل نفّذ:

```bash
./gradlew clean
./gradlew assembleDebug
```

## رابعًا: إصلاح ملفات appwidget-provider XML

أنشئ ملف XML مستقل لكل Widget. يجب تحديد المقاس المناسب والـ resize والـ preview بوضوح.

مثال مبدئي لويدجت الصلاة القادمة:

```xml
<appwidget-provider xmlns:android="http://schemas.android.com/apk/res/android"
    android:minWidth="180dp"
    android:minHeight="72dp"
    android:minResizeWidth="180dp"
    android:minResizeHeight="72dp"
    android:targetCellWidth="3"
    android:targetCellHeight="1"
    android:resizeMode="horizontal|vertical"
    android:updatePeriodMillis="0"
    android:initialLayout="@layout/widget_next_prayer"
    android:previewLayout="@layout/widget_preview_next_prayer"
    android:previewImage="@drawable/widget_preview_next_prayer"
    android:widgetCategory="home_screen"
    android:description="@string/widget_description_next_prayer" />
```

طبّق ما يناسب كل Widget:

- Widget الصلاة القادمة: صغير أو متوسط.
- مواقيت الصلاة: متوسط أو كبير.
- آية اليوم: متوسط أو كبير وقابل للتمدد.
- عداد التسبيح: صغير أو متوسط.
- القرآن: متوسط أو كبير.
- الطقس: متوسط.
- الخطة اليومية: كبير.
- مشغل القرآن: متوسط.
- ويدجت القبلة: متوسط، مع فتح شاشة القبلة عند النقر.

لا تستخدم `minWidth` و`minHeight` متطابقين لجميع الويدجت.

استخدم `previewLayout` أو `previewImage` بطريقة صحيحة حسب تقنية الواجهة وإصدار Android. إذا كان Launcher لا يعرض `previewLayout`، وفر `previewImage` مخصصًا لكل Widget أيضًا. لا تستخدم شعار التطبيق كـ preview إلا لو كانت الويدجت نفسها شعارًا أو اختصارًا.

---

## خامسًا: إنشاء تصميم Preview مطابق للتصميم الحقيقي

لكل Widget أنشئ Preview مستقلًا يظهر في قائمة اختيار الويدجت بنفس الشكل العام الذي سيظهر بعد إضافته.

يجب أن تتضمن المعاينة:

- عنوان Widget الصحيح.
- الألوان الحقيقية.
- الأيقونة الخاصة بالوظيفة، لا أيقونة التطبيق العامة فقط.
- ترتيب النصوص الحقيقي.
- المقاس التقريبي الحقيقي.
- حالة بيانات واضحة.

أمثلة:

- Preview الصلاة القادمة يعرض بطاقة باسم «الصلاة القادمة» وأيقونة صلاة ووقتًا بصيغة معاينة مفهومة، وليس شعار التطبيق فقط.
- Preview آية اليوم يعرض بطاقة قراءة مزخرفة باسم «آية اليوم».
- Preview عداد التسبيح يعرض عدادًا وزرًا أو دائرة تسبيح.
- Preview مواقيت الصلاة يعرض قائمة الصلوات.
- Preview مشغل القرآن يعرض اسم السورة وأزرار التشغيل.

إذا كانت المعاينة تحتاج نصًا تمثيليًا، استخدم نص Preview واضحًا مثل «معاينة الصلاة القادمة»، وليس وقتًا حقيقيًا قد يضلل المستخدم. أما عند تشغيل الويدجت الفعلية فاستخدم البيانات الحقيقية من التطبيق.

## سادسًا: أسماء وتصنيفات الويدجت

أنشئ أسماء عربية مميزة وقصيرة. لا تجعل الاسم هو «نور المسلم» لجميع العناصر.

استخدم مثلًا:

| النوع | الاسم الظاهر |
|---|---|
| Next prayer | الصلاة القادمة |
| Prayer times | مواقيت الصلاة |
| Ayah | آية اليوم |
| Dhikr | ذكر اليوم |
| Quran progress | تقدم الختمة |
| Tasbeeh | عداد التسبيح |
| Qibla | اتجاه القبلة |
| Hijri date | التاريخ الهجري |
| Last reading | آخر قراءة |
| Weather | الطقس |
| Worship plan | خطة العبادة |
| Quran player | مشغل القرآن |
| Ramadan | مواقيت رمضان |

أضف أوصافًا قصيرة لكل Widget باستخدام `android:description` إن كان الإصدار يدعم ذلك، مع ترجمة عربية واضحة.

## سابعًا: إصلاح Configuration Activity

بعض الويدجت تحتاج إعدادًا قبل الإضافة، وبعضها لا تحتاج. طبّق القاعدة التالية:

### الويدجت التي لا تحتاج إعدادًا
يجب أن تُضاف مباشرة دون Configuration Activity، مثل:

- التاريخ الهجري.
- الصلاة القادمة عند توفر الموقع أو آخر إعداد محفوظ.
- آية اليوم.
- ذكر اليوم.

إذا كانت البيانات المطلوبة غير متاحة، أضف الويدجت بحالة فارغة واضحة مع زر يفتح التطبيق لإكمال الإعداد، ولا تفشل عملية الإضافة.

### الويدجت التي تحتاج إعدادًا
أنشئ Configuration Activity حقيقية عند الحاجة، مثل:

- اختيار نوع المدينة أو الموقع.
- اختيار القارئ.
- اختيار نوع الذكر.
- اختيار الوجهة في Widget الطقس أثناء السفر.
- اختيار نوع الخلفية أو المظهر.

يجب أن تقوم Configuration Activity بما يلي:

1. تستقبل `EXTRA_APPWIDGET_ID`.
2. تتحقق من أنه صالح.
3. تحفظ إعدادات هذا ID فقط.
4. تستدعي تحديث Widget المحدد.
5. تعيد `RESULT_OK` مع `EXTRA_APPWIDGET_ID`.
6. تعيد `RESULT_CANCELED` عند الإلغاء.
7. لا تستخدم ID ثابتًا لجميع الويدجت.
8. لا تنهار عند إغلاق المستخدم للشاشة.

مثال النتيجة المطلوبة عند النجاح:

```kotlin
val resultIntent = Intent().apply {
    putExtra(AppWidgetManager.EXTRA_APPWIDGET_ID, appWidgetId)
}
setResult(Activity.RESULT_OK, resultIntent)
finish()
```

راجع Manifest الخاص بـ Configuration Activity، وتأكد من أن class وintent والـ exported flags صحيحة.

## ثامنًا: إصلاح خطأ Couldn't add widget

تحقق من جميع الأسباب المحتملة، ولا تكتفِ بإخفاء الخطأ:

1. Receiver غير موجود أو class path خاطئ.
2. `android:exported` غير صحيح.
3. غياب `APPWIDGET_UPDATE` intent-filter.
4. ملف `appwidget-provider` غير صالح أو يحتوي resource غير موجود.
5. `initialLayout` مفقود أو يحتوي View غير صالح.
6. Preview غير موجودة أو resource تالفة.
7. Configuration Activity غير موجودة أو لا تعيد `RESULT_OK`.
8. استخدام `AppWidgetManager.EXTRA_APPWIDGET_ID` بشكل خاطئ.
9. Crash أثناء `onUpdate` أو `onEnabled`.
10. Crash أثناء تحميل Room أو DataStore على Main Thread.
11. استخدام Context أو Coroutine غير صحيح داخل Provider.
12. محاولة طلب صلاحية موقع من Receiver أثناء إضافة الويدجت.
13. عدم وجود حالة Offline أو بيانات فارغة.
14. Resource أو drawable كبير جدًا أو غير صالح.
15. تعارض بين Jetpack Glance وRemoteViews في نفس التعريف.
16. Provider مكرر أو XML مرتبط بـ class خاطئ.
17. مشكلة في `PendingIntent` أو flags على Android الحديث.

ضع حماية قوية داخل دورة حياة الويدجت:

- لا تسمح لأي Exception بالخروج من `onUpdate`.
- استخدم logging آمنًا في Debug فقط.
- إذا فشل تحميل البيانات، اعرض Layout خطأ لطيفًا مع زر إعادة المحاولة.
- لا تفشل إضافة الويدجت بسبب عدم وجود إنترنت أو موقع.
- نفّذ العمل غير المتزامن بطريقة متوافقة مع AppWidget lifecycle.
- لا تنفذ استعلامات قاعدة البيانات على Main Thread.
- افحص كل Resource قبل البناء.

## تاسعًا: منع التكرار في Launcher

بعد إزالة التعريفات المكررة من الكود، يجب مراعاة أن Launcher قد يحتفظ ببيانات قديمة.

أضف في تقرير README تعليمات اختبار نظيفة:

1. إزالة الويدجت القديمة من الشاشة الرئيسية.
2. إيقاف التطبيق.
3. إلغاء تثبيت التطبيق عند الحاجة في بيئة الاختبار.
4. تثبيت APK الجديد.
5. إعادة تشغيل Launcher أو الجهاز عند الحاجة.
6. فتح قائمة Widgets من جديد.

لا تعتمد على هذه الخطوات كحل للتكرار داخل التطبيق؛ يجب أولًا حذف التعريفات المكررة من Manifest وResources.

استخدم أسماء Classes وXML مستقرة في الإصدار النهائي. إذا احتجت إلى إزالة Provider قديم، وثّق قرار الإزالة ولا تنشئ Alias جديدًا يعيد نفس النسخة.

## عاشرًا: اختبار كل Widget تلقائيًا

أنشئ جدول اختبار يحتوي على كل Widget، ويجب أن يمر كل عنصر بالاختبارات التالية:

1. يظهر مرة واحدة فقط في قائمة Widgets.
2. يظهر باسمه الصحيح.
3. يظهر Preview الصحيح.
4. يعرض المقاس الصحيح.
5. يمكن إضافته إلى الشاشة الرئيسية.
6. لا تظهر رسالة `Couldn't add widget`.
7. يفتح التطبيق عند الضغط على العنصر القابل للنقر.
8. يعمل دون إنترنت إذا كانت وظيفته تعتمد على بيانات محلية.
9. لا ينهار عند رفض الموقع.
10. يتحدث عند تغير اليوم.
11. يتحدث عند تغيير الإعدادات.
12. يحافظ على إعداداته بعد إعادة تشغيل الجهاز.
13. يتغير بشكل صحيح بين الوضع الداكن والفاتح.
14. يعمل مع RTL.
15. يمكن حذفه من الشاشة دون ترك أخطاء.

اختبر على Android 12 وAndroid 13 أو أحدث إن أمكن، وعلى Launcher مختلف إن أمكن.

## الثاني عشر: المخرجات المطلوبة

بعد التنفيذ سلّم ما يلي:

1. جميع ملفات Widget Providers بعد الإصلاح.
2. جميع ملفات `appwidget-provider` XML.
3. جميع ملفات Preview وLayouts.
4. AndroidManifest محدثًا دون تعريفات مكررة.
5. أسماء وDescriptions عربية فريدة.
6. Configuration Activities المصححة.
7. تحديث `WIDGETS_CATALOG.md` بجدول كامل.
8. تقرير يوضح التعريفات التي حُذفت بسبب التكرار.
9. تقرير يوضح سبب وحل خطأ `Couldn't add widget`.
10. اختبارات نجاح الإضافة لكل Widget.
11. APK بعد نجاح البناء.
12. تعليمات اختبار Launcher النظيف.

## معيار الإكمال النهائي
لا تعتبر المرحلة مكتملة إلا إذا تحققت الشروط التالية:

- كل Widget يظهر باسمه الحقيقي، وليس «نور المسلم» فقط.
- لكل Widget Preview وتصميم يطابقان وظيفته.
- لا توجد Widgets مكررة في القائمة.
- لا تظهر كل الويدجت بحجم 2x1 بلا سبب.
- كل Widget يمكن إضافته إلى الشاشة الرئيسية.
- لا تظهر رسالة `Couldn't add widget`.
- الويدجت التي تحتاج إعدادًا تفتح Configuration Activity وتغلق بنجاح.
- الويدجت التي لا تحتاج إعدادًا تُضاف مباشرة.
- لا توجد بيانات وهمية أو أزرار غير فعالة.
- ينجح البناء والاختبار على Android الحديث.
