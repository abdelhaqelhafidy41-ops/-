# المرحلة الخامسة: الإعدادات والإحصائيات والخصوصية والعمل دون اتصال

## السياق
استكمل تنفيذ تطبيق نور المسلم بعد المراحل الأربع السابقة. اعتبر الوظائف السابقة حقيقية، ولا تستبدلها ببيانات تجريبية أثناء هذه المرحلة.

## الهدف
إكمال تجربة المستخدم بإعدادات شاملة، إحصائيات حقيقية، سياسة خصوصية، وإستراتيجية Offline-First موثوقة.

## صفحة الملف الشخصي والإحصائيات
اعرض بيانات ناتجة من استخدام المستخدم الفعلي، وليس أرقامًا ثابتة:

- إنجاز اليوم.
- سجل الصلوات التي علّمها المستخدم كمؤداة.
- عدد الأذكار المكتملة.
- صفحات أو آيات القرآن المقروءة.
- أيام الاستمرارية.
- تقدم الختمة.
- تقدم الحفظ.
- إحصائيات أسبوعية وشهرية.
- رسوم بسيطة وواضحة، مع بديل نصي مناسب لسهولة الوصول.
- حالة فارغة مفهومة عند عدم وجود بيانات.

أضف:

- تصدير البيانات بصيغة مناسبة مثل JSON أو CSV.
- حذف جميع البيانات بعد تأكيد واضح.
- عدم حذف البيانات عند تسجيل الخروج الوهمي أو تغيير المظهر.

## الإعدادات
نفّذ إعدادات تعمل فعليًا:

- اللغة العربية، مع بنية قابلة لإضافة الإنجليزية.
- الوضع الفاتح والداكن والتلقائي.
- حجم الخط ونوعه.
- طريقة حساب الصلاة.
- المذهب.
- المدينة أو الموقع.
- الإشعارات لكل نوع.
- صوت الأذان.
- القارئ المفضل.
- تنزيل المحتوى دون اتصال.
- تشغيل الاهتزاز.
- سياسة الخصوصية.
- شروط الاستخدام.
- مصادر المحتوى والتراخيص.
- حول التطبيق.
- التواصل مع المطور.
- إعادة ضبط الإعدادات.
- حذف البيانات.

كل تغيير يجب أن يُحفظ عبر DataStore أو Room وأن ينعكس فورًا على التطبيق.

## Offline-First
تأكد من تخزين:

- القرآن بعد التنزيل.
- الأذكار والمكتبة المتاحة.
- المفضلة.
- آخر موضع قراءة.
- الإحصائيات.
- الإعدادات.
- آخر موقع.
- آخر مواقيت محسوبة.

عند انقطاع الإنترنت:

- تعمل القراءة والأذكار والمفضلة والإحصائيات.
- تعمل مواقيت الصلاة بالحساب المحلي عند توفر الموقع.
- تظهر آخر مواقيت مخزنة مع تاريخها بوضوح.
- لا تعرض طقسًا أو صوتًا أو محتوى غير متوفر على أنه متاح.
- توفر أزرار إعادة المحاولة.

استخدم استراتيجية تحديث آمنة: لا تحذف النسخة القديمة قبل نجاح النسخة الجديدة، ونفّذ Room migrations.

## الخصوصية والأمان
1. أنشئ سياسة خصوصية حقيقية داخل التطبيق وملفًا مستقلًا.
2. اشرح استخدام الموقع والإشعارات والصوت والإنترنت.
3. اطلب الموقع بعد موافقة المستخدم وفي سياق الميزة.
4. لا تجمع الموقع أو بيانات العبادة دون ضرورة.
5. لا تستخدم تحليلات تجمع بيانات حساسة دون موافقة.
6. استخدم HTTPS.
7. لا تضع مفاتيح API في المستودع.
8. نفّذ حذف البيانات محليًا.
9. لا تعرض Stack Trace للمستخدم.
10. أضف شاشة مصادر البيانات والتراخيص.

## الوصولية والأداء
- دعم TalkBack.
- contentDescription لكل زر.
- تباين كافٍ.
- دعم تكبير النص.
- عدم الاعتماد على اللون وحده.
- LazyColumn وPaging حيث يلزم.
- عدم تشغيل أعمال خلفية كثيفة بلا داعٍ.
- احترام البطارية.

## الاختبارات
أضف أو حدّث:

- اختبارات DataStore.
- اختبارات Room migrations.
- اختبارات حذف وتصدير البيانات.
- اختبارات Offline-First.
- اختبارات الوضعين الفاتح والداكن.
- اختبارات الإحصائيات المشتقة من السجلات.
- اختبارات RTL والوصولية الأساسية.

## التحقق النهائي
- افصل الإنترنت واختبر الوظائف الأساسية.
- غيّر الإعدادات ثم أعد تشغيل التطبيق.
- احذف البيانات وتأكد من الحذف الحقيقي.
- صدّر البيانات وتحقق من الملف.
- شغّل الاختبارات والبناء.
